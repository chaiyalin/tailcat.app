Security model · 安全模型

安全说明 / Security notes

加密保护网络链路中的内容；它不验证参与者身份，也不能保护已被控制的终端或危险文件。多人群聊还必须信任房主。请在使用前了解边界。

Encryption protects content on each network link. It does not authenticate participants or protect a compromised endpoint or dangerous file, and group text additionally requires trusting the host. Understand the boundary before use.

中文

1. 保护范围

  • 文字、语音留言、通话信令及中继文件使用 Tailcat WireGuard；启用原生文件直传时，可靠 DataChannel 文件正文使用 WebRTC DTLS；
  • 群聊成员与房主之间的控制及文字链路使用 WireGuard；点对点文件正文不经过房主。文件直传同样可能暴露双方公网 IP，不申请媒体权限；
  • 仅一对一房间提供实时语音、视频和屏幕媒体，并由浏览器 WebRTC 使用 DTLS-SRTP 加密；
  • 网站为静态应用，无账号、消息数据库、文件托管、聊天历史、离线队列或内容恢复；
  • 私人一对一房间中，不超过 100 MiB 的文件仅在安全 OPFS 临时存储和可信容量估算可用时自动接收；每个已认证会话最多自动接收 20 个文件、累计 500 MiB，零字节也计一件，达到任一上限后改为手动确认，新会话重置。超过 100 MiB 或无法安全暂存时仍须接收者确认并选择位置。多人文件始终逐接收者确认。文件不会被自动打开、预览或扫描；完整传输须校验声明大小和 SHA-256，再由用户点击打开、保存或分享。

2. 不在保护范围内

  • 元数据：Cloudflare Pages 可处理网页访问元数据；DERP 可观察双方 IP、连接时间、区域、流量大小和模式；
  • WebRTC 地址：通信对端、STUN 服务和相关网络运营方可能看到你的公网 IP 与连接候选；
  • 多人房主：群聊文字由房主读取、排序并转发，因此必须信任房主；这不是对房主隐藏内容的群组端到端加密。房主还可看到昵称、随机成员短码、成员关系、文件大小和接收者；
  • 身份：持有邀请的人可能连接或申请加入。加密地址、可重名昵称和随机成员短码都不是实名认证，项目没有账号或身份验证；
  • 终端：恶意软件、浏览器扩展、操作系统、剪贴板、下载目录、截图、录屏和肩窥可在加密边界之外获取数据；
  • 对端行为：对方可以保存、复制、转发或重新录制其收到的内容；
  • 文件安全：本站不做病毒扫描、沙箱执行、内容审核或文件真实性验证。

3. 安全使用建议

  1. 只通过已验证的可信渠道发送完整邀请链接，并在其他渠道确认通信对象；多人房主应逐项核对加入申请，并在邀请外泄时立即轮换；
  2. 不要公开发布房间地址，不要把持久地址用于陌生人或长期敏感用途；
  3. 保持浏览器和操作系统更新，仅使用受支持的桌面 Chrome/Edge、Android Chrome 132+ 或 iOS Safari 17+；
  4. 私人小文件可能自动暂存；看到文件卡片后仍应核对发送者、文件名、大小和用途，并在打开、保存或分享前用本地安全软件检查；
  5. 使用后关闭房间。多人房主离开会为所有人解散房间且不会转移房主；若保存过一对一地址，使用“忘记地址”并在需要时清除本站数据；
  6. 屏幕共享前关闭通知和敏感窗口，结束后确认浏览器的共享指示器消失；
  7. 为重要数据保留原始副本和独立备份，不把传输成功提示当作唯一存档。

4. 网络与可用性

浏览器 Tailcat 当前经公共 DERP 中继传输，公开节点限速、尽力而为、无可用性或吞吐量 SLA。一对一实时通话只配置 STUN，不配置 TURN；在对称 NAT、防火墙或企业网络下可能失败。网络中断、页面进入后台、设备休眠或内存压力都可能终止传输。本测试版没有后台文件传输或文件断点续传。已加入的多人成员可在 120 秒内尝试恢复房主内存中最多 100 条或 8 MiB 的事件；缓冲不足会显示消息缺口。房主页面关闭或刷新会立即解散房间。

5. 浏览器与本地密钥

正式支持桌面 Chrome 和 Edge；Android Chrome 132+ 与 iOS Safari 17+ 为测试支持并应保持前台。手机创建多人房间前必须确认保持页面前台和屏幕唤醒；离开前台会暂停加入与发送，120 秒内未返回会为所有人关闭房间。唤醒锁不能保证后台运行。iOS Chrome、Android Edge、Samsung Internet、Firefox、桌面 Safari 和其他浏览器不属于本版正式目标；若核心能力完整，应用可能提供明确标记的受限模式，但不作兼容性承诺。一对一临时密钥在页面关闭或超时后停止使用；主动保存的一对一地址私钥只应进入本站来源的 IndexedDB。多人房间始终使用临时地址，不复用该密钥。

私人一对一文件不超过 100 MiB 时，浏览器仅在可建立本站来源的 OPFS 临时项，并能可信地估算出文件大小加安全余量所需空间时自动接收。自动接收还限于每个已认证会话最多 20 个文件、累计 500 MiB；零字节也计一件，达到任一上限后，本会话后续文件须手动确认，新会话重置计数。更大的文件或无法安全自动暂存的文件仍须用户确认，并在浏览器支持时选择保存位置；多人文件始终逐接收者确认。OPFS 使用随机传输编号作为内部路径，不会自动打开或预览内容。大小与 SHA-256 校验完成后，用户才能点击打开、保存或分享。OPFS 不是云端备份；导出成功、用户取消分享或传输失败后应删除临时项，其他系统分享错误会保留可供本地下载或手动删除的副本。仍应避免把重要文件的唯一副本交给浏览器存储。

6. 报告安全问题

请把可复现步骤、受影响版本、预期与实际结果、影响评估和最小化的证明发送至 abuse@tailcat.app。不要发送真实私钥、完整邀请、第三方个人数据、非法内容或可直接利用生产用户的攻击代码。请先给予合理修复时间再公开披露。

本项目暂不承诺漏洞赏金、响应时间或安全港。测试应遵守法律、可接受使用政策，并避免自动扫描、拒绝服务、持久化访问或接触其他用户内容。

7. 滥用事件

若是骚扰、恶意文件、非法内容或其他使用问题，也请联系 abuse@tailcat.app。由于本站运营方无法读取传输内容，且服务无账号或历史数据库，可调查证据有限；多人房主能看到群聊文字不代表运营方能看到。紧迫危险请联系当地紧急服务。

English

1. What is protected

  • Text, voice notes, call signaling and relayed files use Tailcat WireGuard. Enabled native file bodies use reliable WebRTC DataChannels with DTLS;
  • Group member-to-host control and text links use WireGuard; peer-to-peer file bodies bypass the host. Direct files can also expose public IPs, without requesting media permissions;
  • Live audio, video, and display media is available only in private rooms and is encrypted by browser WebRTC with DTLS-SRTP;
  • The site is static and has no account, message database, file hosting, chat history, offline queue, or content recovery; and
  • In a private one-to-one room, a file up to and including 100 MiB is automatically received only when safe OPFS staging and a trustworthy capacity estimate are available. Each authenticated session can auto-receive at most 20 files and 500 MiB in total; zero-byte files count, reaching either limit makes later files manual, and a new session resets the counters. A larger file or one that cannot be staged safely still requires recipient approval and a selected destination. Every group file requires per-recipient approval. Files are never automatically opened, previewed, or scanned; a complete transfer verifies declared size and SHA-256 before the user clicks to open, save, or share.

2. What is not protected

  • Metadata: Cloudflare Pages can process site-access metadata; DERP can observe peer IPs, connection time, region, traffic volume, and traffic patterns;
  • WebRTC addresses: Your peer, the STUN service, and relevant network operators may see your public IP address and connection candidates;
  • Group host: The host reads, orders, and relays group text, so members must trust the host; this is not host-blind group end-to-end encryption. The host can also see nicknames, random member codes, membership, file sizes, and recipients;
  • Identity: A person holding an invitation may connect or request admission. An encrypted address, duplicate-capable nickname, or random member code is not verified identity, and the project has no account or identity service;
  • Endpoints: Malware, browser extensions, the operating system, clipboard, downloads, screenshots, recordings, and shoulder surfing can expose data outside the encryption boundary;
  • Peer behavior: A peer can save, copy, forward, or re-record anything received; and
  • File safety: The site performs no malware scan, sandbox execution, content moderation, or authenticity check.

3. Safer use

  1. Send a complete invitation only through a verified, trusted channel and confirm intended participants out of band; group hosts should inspect each request and rotate a leaked invitation immediately;
  2. Do not post room addresses publicly or reuse a persistent address with strangers or for long-lived sensitive work;
  3. Keep the browser and operating system current, and use supported desktop Chrome/Edge, Android Chrome 132+, or iOS Safari 17+;
  4. A small private-room file may be staged automatically; when its card appears, still confirm its sender, name, size, and purpose, then inspect it with local security software before opening, saving, or sharing;
  5. Close the room after use. A group host leaving ends the room for everyone with no host transfer. If you saved a private-room address, use “forget address” and clear site data when appropriate;
  6. Before screen sharing, close notifications and sensitive windows, and verify the browser's sharing indicator is gone afterward; and
  7. Keep originals and independent backups of important data; never treat a transfer-success message as your only archive.

4. Network and availability

Browser Tailcat traffic currently uses public DERP relays, which are rate-limited, best-effort, and have no uptime or throughput SLA. Private-room live calls configure STUN only, with no TURN fallback, so symmetric NAT, firewalls, or enterprise networks can prevent a call. Network loss, backgrounded pages, device sleep, or memory pressure can terminate a transfer. This beta has no background file transfer or file resume. An existing group member can attempt a 120-second reconnect using at most 100 events or 8 MiB still in the host's memory; a missing range is reported as a message gap. Closing or refreshing the host page immediately ends the room.

5. Browsers and local keys

Desktop Chrome and Edge are supported; Android Chrome 132+ and iOS Safari 17+ are foreground-only beta targets. Hosting a group on a phone requires acknowledging that the page and screen must remain in the foreground. Backgrounding pauses joins and sends; failure to return within 120 seconds ends the room for everyone. A wake lock cannot guarantee background operation. iOS Chrome, Android Edge, Samsung Internet, Firefox, desktop Safari, and other browsers are not release targets. When their core capabilities are complete, the app may offer an explicitly limited mode without a compatibility commitment. Private-room ephemeral keys stop being used when the page closes or times out. A deliberately remembered private-room address key should exist only in this origin's IndexedDB; group rooms always use ephemeral addresses and do not reuse that key.

For a private one-to-one file up to and including 100 MiB, the browser automatically receives only when it can create an origin-private OPFS temporary entry and can reliably estimate space for the file plus a safety margin. Automatic receive is also limited to 20 files and 500 MiB in total per authenticated session; a zero-byte file counts as one, reaching either limit makes later files in that session manual, and a new session resets the counters. A larger file, or one that cannot be staged automatically and safely, still requires user approval and a selected destination where supported; every group file requires per-recipient approval. OPFS uses a random transfer identifier as its internal path and never opens or previews content automatically. The user may click to open, save, or share only after size and SHA-256 verification. OPFS is not a cloud backup; the temporary entry should be removed after export, user-cancelled sharing, or transfer failure. Other system-share errors retain a copy for local download or manual deletion, and important data must retain an independent original.

6. Reporting a security issue

Send reproducible steps, affected version, expected and actual behavior, impact assessment, and a minimal proof to abuse@tailcat.app. Do not send real private keys, complete invitations, third-party personal data, illegal content, or exploit code that directly endangers production users. Allow reasonable time for a fix before public disclosure.

The project does not currently promise a bounty, response time, or safe harbor. Testing must follow the law and Acceptable Use Policy and avoid automated scanning, denial of service, persistent access, or access to another user's content.

7. Abuse incidents

For harassment, malicious files, illegal content, or other use issues, also contact abuse@tailcat.app. The operator's inability to read transferred content and the absence of accounts or a history database limit available evidence; a group host's access to group text does not give the operator that access. Contact local emergency services for immediate danger.
